Intent: drawing the fence

Before anyone writes a line of code, one page says what the agent is for and where it may never go.

Surveyors come before builders

Before a house goes up, a surveyor hammers stakes into the ground: this is the plot, that is the neighbour's land. Nobody argues about the fence later because it was agreed before the first brick.

intent.md is those stakes. It is step 1 of the lab, and AGENTS.md tells the AI assistant to read it before changing anything.

1
Outcome

One observable result in plain words: what the reader opens each morning, and what they no longer have to do.

2
Success checks

Tick-boxes a stranger can verify with one command or one look.

3
Boundary

What is in scope, what is forbidden, and when to stop and ask a human.

4
Owners

Three named roles: the Reader, the Maintainer and the Gate.

5
Evidence contract + OPEN

What counts as proof, and a list of every unknown, written down instead of guessed.

Success checks: written for a stranger

The template's own placeholder text tells you how to write a good check. Read the hints closely; they are the lesson.

intent.md 
## Success checks

- [ ] `TEMPLATE — a check a fresh reader can verify with one command or one look, without the author in the room.`
- [ ] `TEMPLATE`
- [ ] `TEMPLATE`
- [ ] `OPEN — a check that needs a live run or an access you do not have yet.`
PLAIN ENGLISH

A section heading. The ## is Markdown for "second-level heading."

 

Check one: someone who has never met you must be able to confirm it, by running a command or glancing at a page.

Check two: same rule.

Check three: same rule.

Check four is honest about what you cannot prove yet, like a live run you have no access for. It is marked OPEN, not quietly dropped.

💡
"Without the author in the room"

This phrase is the key to working with AI. The AI is always "the author who is not in the room" tomorrow. If a check needs you to explain it, it cannot catch a mistake the AI made while you were not looking.

The boundary: four stakes in the ground

This is the most important block in the whole lab. Every later document points back to it.

intent.md 
## Boundary

- In scope: `TEMPLATE — the folder, the sources, the outputs.`
- Out of scope: `TEMPLATE — what the agent may never do: write to a source, send anything, store a credential.`
- The model never invents a fact: `TEMPLATE — what happens when a source is silent.`
- Stop or escalate when: `TEMPLATE — a write scope is offered, personal data appears, the agent starts deciding instead of describing.`
PLAIN ENGLISH

The fence itself.

 

Inside the fence: which folder the work lives in, which tools get read, what files come out.

Outside the fence: never change anything in a source, never send a message, never keep a credential.

If a source says nothing (say, the calendar is empty), the brief must say that, not make something up. This guards against hallucination.

Tripwires: if someone offers a write scope, if private data shows up, or if the agent starts making decisions instead of describing facts, halt and hand it to a human.

Three owners, three different jobs

📖
Reader

"Reads the brief, decides what to push." The person the agent works for.

🔧
Maintainer

"Owns the contract, the prompt, the schedule." Fixes it when it breaks.

🚦
Gate

"Reads every pull request against this file before merge." The human who says yes or no.

Splitting these roles means nobody grades their own homework, including the AI.
