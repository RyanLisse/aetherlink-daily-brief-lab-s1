What this lab builds

One morning brief, seven steps, and a repository that starts out empty on purpose.

Picture Tuesday, 8:00 in the morning

You open one page. It tells you which code reviews are waiting, which tickets moved overnight, which wiki page someone edited, and what is on your calendar. You did not write it. An agent did.

That is the thing this lab builds: a daily brief agent. It reads your work tools every morning and writes a one-page brief.

Read, never write

The agent only reads these sources. It never posts a comment, closes a ticket or sends an email. You will see this rule come back in almost every document of the lab.

The surprise: there is almost no code

Open the repository and you find documents, not software. The branch called main holds templates and a package skeleton. Nothing else.

That emptiness is the lesson. You are meant to fill the documents first, and the code only after the documents say what it must do.

The whole route in one table

The README lays out every step as a row. Read it as a contract: each step names the file you write and the proof that the step is really done.

README.md 
| Step | Phase | You write | Proof |
| --- | --- | --- | --- |
| 1 | Plan | `intent.md` | A facilitator accepts the boundary |
| 2 | Plan | `docs/spec.md`, `src/brief.ts`, `sample/brief.sample.json`, `test/schema.test.ts` | `npm test` green on the schema tests |
| 3 | Design | `docs/design.md`, one ADR, `docs/plan.md` | A stranger can follow the plan and name what proves completion |
| 4 | Build | `src/render.ts`, `src/main.ts` | `npm run brief:sample` writes `out/latest.html` |
| 5 | Build | `src/sources.ts`, `src/agent.ts` | `npm test` and `npm run typecheck` green; wiring proven without a network |
| 6 | Test | `docs/evidence.md` and one screenshot | Three commands with exit codes and a reviewer |
| 7 | Deploy | `docs/gate.md`, `gitlab-ci.example.yml` | PASS / FAIL / OPEN with a quoted line |
PLAIN ENGLISH

Four columns: which step, which phase of the work, what you produce, and how anyone can tell it is finished.

(Table divider, required by Markdown.)

Step 1: write down what you want. Done when a human accepts where the fence is.

Step 2: describe the brief's exact shape, then write tests that check it. Done when those tests pass.

Step 3: design the parts, record one decision (an ADR), write a plan. Done when a stranger could follow it.

Step 4: the first real code. Done when a sample brief turns into an HTML page.

Step 5: connect the real sources. Done when tests and the typecheck pass without touching the internet.

Step 6: record proof. Done when three commands, their exit codes and a second person are written down.

Step 7: a human decides whether to ship, quoting the line that convinced them.

💡
Every step has a "how would I know?"

Notice that no row says "done when it feels finished." Each proof is something another person can check without you in the room. That habit is what lets you trust work an AI did for you.
